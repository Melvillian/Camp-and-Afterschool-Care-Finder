# Site Bug Fixes — Design

*2026-11-20. Status: awaiting approval.*

## Intent

Eight defects were found while running the site locally and on GitHub Pages. One makes the Afterschool page unusable; the rest make the site look empty out of season, hide camps from the map, or leave the data fragile. Fix all eight before 2027 camp data is added, so new data lands on a site that displays it correctly.

## Goals

1. `afterschool.html` lists its 10 programs with no console error.
2. Out of season, the Camps page does not open on a mostly empty list.
3. Every program with a known Vermont town appears on the map.
4. The exported CSV has a clean "Full Address" value.
5. No 404 for a favicon.
6. The admin page never silently shows an old local copy of the data.
7. A program keeps the same `uid` across rebuilds.
8. Text from the CSVs cannot inject markup into a page.

## Non-goals

- No redesign of filters, cards, calendar or map.
- No change to the CSV schema.
- No new runtime or build dependencies.
- The "likely" badge (upstream issues #5, #7) and the dev server's save endpoint are out of scope.

## Anti-goals

- A fix that needs a bundler, `npm install` or `pip install`. The site must stay "clone and open".
- Hiding last season's camps with nothing in their place.
- Discarding an admin user's unsaved edits without telling them.

## Constraints

- Static site served by GitHub Pages from the `main` branch root. Plain `<script>` tags, no modules.
- Python scripts use the standard library only.
- `data.js` is generated by `scripts/build_data_js.py` and committed; it is never edited by hand.
- There are no automated tests today. This work adds the first ones.

## Approaches

**A. Patch each bug in place, no tests.** Smallest diff. Rejected: bug 1 was a one-line regression that nobody noticed because nothing checks that both pages load.

**B. Patch in place, plus a small zero-dependency test setup (chosen).** Pure logic moves into a new `lib.js` that works both as a browser script and as a Node module, tested with Node's built-in runner. Python logic is tested with `unittest`. A smoke script loads the real pages in headless Chrome against fixture data. No packages to install.

**C. Restructure `app.js` into modules with a bundler and a DOM test library.** Best long-term testability. Rejected: breaks "clone and open", and upstream issue #11 shows the project already struggles with npm tooling.

B was chosen by Claude as the recommended option; it has not yet been confirmed by Melvillian.

## Decisions per bug

Each is Claude's call unless marked otherwise.

| # | Bug | Decision |
|---|---|---|
| 1 | Afterschool page crash | `app.js` treats `filterDate` as optional. The date filter stays camps-only. |
| 2 | Camps hidden out of season | When a category has dated programs and none are upcoming, "Include past programs" defaults to on and a notice says the listings are last season's. When any upcoming program exists, behaviour is unchanged. |
| 3 | Map coverage | Town coordinates are generated at build time from the Vermont town GeoJSON already in the repo, replacing the hand-written list of 21 cities. Programs with no town get a count note under the map, like the calendar's undated note. |
| 4 | Export address | "Full Address" is `street, city, ST zip` with blank parts skipped. County is dropped from it because it already has its own column. |
| 5 | Favicon | A `favicon.svg` tent icon linked from all six pages. |
| 6 | Admin stale data | Local edits are stamped with the build they were made against. When local edits are in use, the admin shows a banner saying so, flags when the published data has changed since, and offers a Discard button. Nothing is discarded automatically. |
| 7 | Unstable IDs | `uid` becomes the program's `program_id`, which the validator already requires to be unique and slug-safe. Numeric `id` stays for the admin page. |
| 8 | Raw HTML | Every CSV-derived value is escaped before going into `innerHTML`. Links are only rendered for `http:` and `https:` URLs. |

### Notice copy for bug 2

> These are {year} programs, shown for reference. Dates and prices are from last season; new listings appear as camps announce them.

`{year}` is the latest year among the category's dated programs.

### Banner copy for bug 6

> You are viewing edits saved in this browser on {date}, not the published data.

followed, when the stamps differ, by:

> The published data has changed since then.

## Left to the builder

- The favicon artwork.
- Internal structure of the smoke script.
