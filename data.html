Data Documentation

Schema reference, field descriptions, and sourcing notes for every dataset in this project.

Overview

The site shows two CSV files, data/programs.csv and data/organizations.csv. scripts/build_data_js.py checks them and joins them into data.js, the file the pages load.

New-season (2027) listings reach those two files through an ingestion pipeline with its own files:

  • data/sources.csv: one row per organization, with the page to watch and where it stands (status_2027).
  • data/staging/2027/: draft rows waiting for review, one file per organization, and _organizations.csv for organization facts such as registration dates.
  • A shared Google Sheet where volunteers check the drafts (see the Volunteer page). Its id is in data/ingest_config.json.

Pipeline order for 2027 listings: scripts/watch_sources.py notices that an organization's page mentions the new season → drafts are written to staging (by the extract-camp-listings Claude Code skill where the site's robots.txt allows it, otherwise typed in by a volunteer) → volunteers compare each draft with the page in the Sheet → the maintainer reads each staging file → scripts/merge_staging.py writes the checked rows into the two CSV files, then runs validate_data.py and build_data_js.py. merge_staging.py is the only script that writes 2027 rows. The maintainer's weekly order is pull, merge, watch, extract, push; the full steps are in docs/ingestion/runbook.md.

Correcting an earlier season by hand: edit the CSV → python3 scripts/validate_data.py (check for errors) → python3 scripts/build_data_js.py (regenerate data.js). Utility scripts like backfill_age_grade.py and fetch_descriptions.py run before validation to fill in missing fields.

Programs

data/programs.csv

On the site: … programs (… camps, … afterschool), counted from data.js; rows marked inactive are not counted Updated: 2027 listings: about weekly from mid-December 2026 to mid-March 2027, as organizations post them. Earlier seasons: corrected as needed. Source: Each organization's own public web pages (listed in data/sources.csv). 2027 rows are drafted from those pages and checked against them by volunteers. 2026 rows came from manual research: program websites, direct outreach, Vermont AOE grant data.

The unified program registry. Each row is one program (one session of one camp, or one afterschool program). Foreign key org_id must match a row in organizations.csv — validated by validate_data.py before building.

Organizations

data/organizations.csv

On the site: … organizations, … of them with programs listed (counted from data.js) Updated: As needed Source: Compiled from program websites and direct outreach. Registration dates, financial aid and website are updated by merge_staging.py from facts volunteers check against the organization's page.

The organization registry. Every org_id referenced in programs.csv must exist here. Organization contact info (phone, email, website) is merged into program records at build time and shown in the detail modal.

Data Pipeline Scripts

All scripts live in scripts/ and are run from the project root. scripts/README.md lists every script, including the smaller enrichment ones not described here.

Check and build

scripts/validate_data.py

Validates programs.csv and organizations.csv for foreign key integrity, required fields, enum values and registration dates. Exit code 0 = pass; exit code 1 = errors that block the build.

scripts/build_data_js.py

Runs validate_data.py first (aborts on errors), then joins programs.csv + organizations.csv and writes data.js. Rows marked inactive are left out. Run this after editing either CSV by hand; merge_staging.py runs it for you.

2027 ingestion

Run in the order given in docs/ingestion/runbook.md. None of these scripts run git or write to the Google Sheet.

scripts/sources.py

Maintains data/sources.csv, the list of pages to watch. seed adds a row for each organization not yet listed; robots records whether each site's robots.txt turns AI crawlers away; check lists problems in the file.

scripts/watch_sources.py

Fetches each html and pdf source not checked in the last 6 days, one request every two seconds. Sets status_2027 to posted when a page mentions the season and its text is new, and to changed when an already merged page changes. Sources of kind rec1, gated and manual are never fetched; the maintainer checks those by hand.

scripts/staging.py

The staging area, data/staging/<season>/<org_id>.csv. add and add-org stage draft rows and organization facts from a JSON file (used by the extract-camp-listings skill); check validates them.

scripts/sheet_sync.py

Connects staging with the volunteer Google Sheet. pull downloads the Tasks, Drafts and Orgs tabs through the Sheet's public CSV export, stages the tasks volunteers finished, and writes a copy of the task list with names and notes removed for the Volunteer page. push writes files of new rows and a list of cell changes that the maintainer imports into the Sheet by hand; no script writes to the Sheet. init writes the header rows for a new Sheet.

scripts/merge_staging.py

Writes reviewed staging rows into programs.csv and organizations.csv (--all-ready, --org ORG_ID, or --org-facts ORG_ID for registration dates alone). Sets program_year to the season and confidence to confirmed, turns a row reviewed as delete into inactive, refuses to change a row of another season, runs the validator and the build, and puts both CSVs back if either fails.

Filling in fields

scripts/backfill_age_grade.py

Fills missing grades_min/grades_max from age_min/age_max (and vice versa) in programs.csv using data/age_to_grade.csv. Run before build_data_js.py when adding programs with only age or only grade data.

scripts/enrich_locations.py

Geocodes and standardizes site_address in programs.csv by querying the OpenStreetMap Nominatim API. Fills in missing addresses and normalizes format to "Street, City, VT ZIP".

scripts/fetch_descriptions.py

Fetches program descriptions from registration_url for rows with a blank description in programs.csv. Extracts the <meta name="description"> tag or first paragraph from each URL. Saves progress every 25 rows.

scripts/normalize_times.py

Standardizes start_time and end_time strings in programs.csv to 12-hour format (HH:MM AM/PM), handling inconsistent inputs like "9am", "09:00", "9:00 AM", etc.

Local server

scripts/dev_server.py

Local development server with live reload: python3 scripts/dev_server.py, then open http://127.0.0.1:8000. It runs only on your own machine. It also lets the Admin page (admin.html, a local tool that is not part of the public site) save edits to rows of earlier seasons through POST /__save_csv, which writes only data/programs.csv and data/organizations.csv.
